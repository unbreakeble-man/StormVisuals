# StormVisuals — правила для агента

## Назначение

StormVisuals — клиентский визуальный мод для Minecraft Java Edition 1.21.11 на Fabric. Цель — ясная, полезная информация для игры на серверах: игрок должен быстро понимать состояние выбранного эффекта. Каждая новая функция должна решать конкретную задачу игрока и не загромождать экран.

## Границы задачи

- Делай только то, что пользователь попросил и что необходимо для работоспособности этого запроса. Не добавляй функции, настройки, зависимости, меню, абстракции, рефакторинг соседнего кода и «улучшения на будущее» по собственной инициативе.
- Если требование неоднозначно, сначала изучи проект и выбери минимальную обратимую реализацию; уточняй только то, без чего нельзя продолжить.
- Не меняй игровую механику, сетевые пакеты или поведение сервера ради визуальной функции без отдельного запроса.
- Сохраняй совместимость с обычными серверами: состояние, неизвестное клиенту, не выдавай за достоверное.
- Пиши ответы пользователю кратко и по-русски. После работы сообщай, что сделано, чем проверено и что осталось проверить вручную.

## Java, Fabric и версии

- Цель проекта фиксирована: Minecraft 1.21.11, Java 21, Fabric Loader и Fabric API из `gradle.properties`. Не обновляй версии без необходимости или запроса.
- Используй Mojang mappings, принятые в `build.gradle`. Проверяй имена методов и сигнатуры именно для 1.21.11, а не по памяти или примерам для других версий.
- Клиентский код держи в клиентском entrypoint и не загружай его на сервере. Новые entrypoints, mixin, access widener и сторонние библиотеки добавляй только при конкретной необходимости.
- Предпочитай штатные события Fabric API. Mixin применяй, когда событие не позволяет решить задачу; выбирай точную точку внедрения, проверяй конфликтность и объясняй причину.
- Соблюдай жизненный цикл Minecraft: доступ к `Minecraft`/миру/игроку только когда они существуют; состояние мира очищай при отключении или смене мира, если функция его хранит.
- Не создавай объекты и не выполняй дорогие вычисления каждый кадр без необходимости. Не блокируй игровой/render thread вводом-выводом или ожиданием.
- На каждую задачу проводи минимальную уместную проверку. Для изменений Java/ресурсов запускай `./gradlew.bat build`; если меняется поведение рендера, дополнительно проверяй в клиенте.

## Рендер и OpenGL

- Для версии 1.21.11 сначала изучай актуальные Fabric rendering docs и код Minecraft/Fabric API. Используй штатные HUD/world render events, render state, `GuiGraphics`, `PoseStack`, `RenderType` и render pipeline по месту применения.
- Не вызывай OpenGL из произвольного потока. GL-ресурсы создавай, используй и освобождай в подходящих фазах render thread; учитывай пересоздание окна и перезагрузку ресурсов.
- Прямые вызовы OpenGL/LWJGL допускаются только когда штатный pipeline не покрывает задачу. Перед этим проверь контекст, совместимость с текущим backend и требуемые расширения.
- Следи за матрицами, пространствами координат, глубиной, blending, culling, scissor и порядком отрисовки. Не оставляй изменённое графическое состояние после собственного прохода; корректно закрывай/освобождай буферы, шейдеры и текстуры.
- Визуальный сигнал должен быть однозначным и ненавязчивым. Не рисуй оверлей или эффект, пока он не запрошен; при реализации учитывай масштаб GUI, прозрачность, читаемость и FPS.
