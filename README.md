# StormVisuals

При открытом чате (`T`) ватермарку и Potions можно перемещать: зажмите ЛКМ на блоке и перетащите. Блоки остаются в пределах экрана; позиции сохраняются между запусками игры. Блюр усилен в Click GUI и HUD и сохраняет приглушённые цвета мира (55% насыщенности); поверх него лежит чёрная подложка с непрозрачностью 77%.

Клиентский визуальный мод для Minecraft 1.21.11 / Fabric с Click GUI и HUD.

Мод автоматически сохраняет состояния модулей, настройки, бинды функций и команд, кастомный прицел со всеми элементами и позиции HUD в фиксированный `config/stormvisuals/autosave.json`. Сохранение выполняется в фоне после изменений и завершается при обычном выходе из Minecraft. Отдельного журнала автосейва нет. Старый `crosshair.json` переносится при первом запуске, исходный файл сохраняется.

Во вкладке **Configs** кнопка «Новый конфиг» плавно раскрывает ввод имени. Каждый пресет — один сжатый файл `[название].storm` в `config/stormvisuals/configs/`, без дополнительных файлов. В списке видны имя, дата создания и размер; доступны загрузка, обновление текущими настройками, переименование и удаление. Перезапись и удаление подтверждаются внутри интерфейса. «Папка конфигов» открывает каталог: закиньте туда чужой `.storm` и нажмите «Обновить» либо снова откройте вкладку. Повреждённый файл отмечается в списке и не меняет текущие настройки. Автосейв управляется отдельно от пресетов.

Potions показывает слева активные эффекты игрока: локализованное название, уровень, игровую иконку и время в компактной плашке. Ширина рассчитывается по самому длинному названию с уровнем, высота — по количеству эффектов. Заголовок использует PNG-иконку листьев; фон, блюр и лёгкая тень совпадают с Click GUI. Размер сохраняется в пикселях при смене масштаба GUI. Без эффектов и при F1 блок скрыт. Текст и размеры обновляются четыре раза в секунду; бесконечный эффект показывает `--:--`.

Ватермарка Storm автоматически появляется по центру сверху в игровом мире: круглый логотип, FPS, пинг в ms и оценка TPS с PNG-иконками. Верхние углы прямые, нижние скруглены; фон и блюр совпадают с Click GUI. TPS — оценка, вычисляемая по интервалам серверных пакетов времени; до получения данных и после 5 секунд без обновлений отображается `--`. Ватермарка скрывается вместе с HUD через F1.

В игровом мире нажмите **правый Shift**, чтобы открыть Click GUI из макета `design/`. ЛКМ по карточке меняет её переключатель, ПКМ раскрывает настройки внутри карточки, поиск и разделы работают. Пока это экран настройки: NoRender, Jumpcircles, FullBright и CustomCrosshair не рисуют эффекты в мире. Клавишу открытия можно изменить в управлении Minecraft. Окно занимает не более 60% экрана. Под ним работает отдельный усиленный Gaussian blur с тёмной подложкой, независимо от настройки блюра меню Minecraft. Монохромные PNG-иконки используют трилинейные mipmap-уровни и четыре выборки альфа-канала на пиксель; ресурсы лежат в `assets/stormvisuals/textures/gui/icons/`. Mipmap-уровни готовятся при загрузке ресурсов в фоновом потоке. Открытие и закрытие (`Esc` или клавиша GUI), смена категорий, переключатели, раскрытие настроек и прокрутка анимированы с сохранением скорости при повторном переключении. Включённые карточки имеют слабый синий фон. Курсор поиска остаётся видимым при вводе и плавно мигает во время паузы.

TargetESP включается карточкой или клавишей `R`. ПКМ открывает дропдаун «Цели», в котором можно одновременно выбрать «Животные», «Игроки», «Голые» (без предметов в четырёх слотах брони) и «Мобы». Пустой выбор никого не выделяет. Отдельный дропдаун «Стиль» предлагает «Души», «Круг», «Кристаллы» и «Маркер». Души — три ярких огонька со светлым ядром и короткими гибкими хвостами из PNG glow. Круг плавно движется по высоте цели с замедлением у границ и коротким вертикальным следом из одного цилиндрического слоя. Кристаллы — 14 вращающихся гранёных фигур со свечением по присланному примеру. Маркер использует предоставленную PNG по центру проекции хитбокса, замедляется и меняет направление вращения. Все стили учитывают глубину мира, плавно появляются и затухают; при смене цели/мира или стиля история душ очищается. Цвет задаётся через «Цвет → Настроить» (HSV/HEX) и применяется ко всем стилям. Используются штатные Fabric world render events и render pipeline Minecraft 1.21.11; по умолчанию модуль выключен.

Рендер GUI кеширует фильтрованные карточки и геометрию текста, пропускает полностью отсечённые элементы и использует один квад для ректов без скругления. Блюр ограничен областью окна с запасом под ядро и обновляется максимум 60 раз в секунду; анимации продолжают работать на текущем FPS. Кеш MTSDF ограничен 512 строками. Это оптимизация нагрузки рендера мода в Minecraft, а не изменение игровой механики или серверной логики.

HUD-слои регистрируются через `HudRenderSystem.addLayer(...)` до вызова `HudRenderSystem.initialize()` в клиентском entrypoint. Слой получает штатные `GuiGraphics` и `DeltaTracker` для Minecraft 1.21.11. Система сама размещает слой перед чатом и не вызывает его вне игрового мира.

`RoundedRectRenderer.draw(graphics, rect)` рисует прямоугольник через GLSL с независимым радиусом четырёх углов и цветом ARGB. Параметры можно менять каждый кадр без пересоздания шейдера. Радиусы автоматически ограничиваются половиной меньшей стороны.

Интерфейс и HUD используют Montserrat Medium (500) для русского и английского текста и цифр. Исходный `Montserrat-Medium.ttf`, набор символов `montserrat_charset.txt`, метаданные `montserrat_medium_mtsdf.json` и лицензия OFL лежат в `src/main/resources/stormvisuals/font/`; PNG-атлас — в `src/main/resources/assets/stormvisuals/textures/font/`. Атлас создан официальным `msdf-atlas-gen` 1.4 с параметрами `-type mtsdf -size 48 -pxrange 8 -potr -yorigin top`.

Нужен JDK 21. Сборка: `./gradlew.bat build`. Запуск клиента для разработки: `./gradlew.bat runClient`. Готовый мод: `build/libs/stormvisuals-0.1.0.jar`; для обычного запуска нужны Fabric Loader и Fabric API той же версии Minecraft.

## Проверка изменений без перезапуска Minecraft

Нужен JDK 21, указанный в `JAVA_HOME`. IDE и дополнительные библиотеки мода не требуются. `runHotSwapClient` использует отдельный **JetBrains Runtime 21 с DCEVM** и флагом `-XX:+AllowEnhancedClassRedefinition`: это позволяет менять структуру уже загруженных классов. При первом запуске официальный архив JBR 21.0.11-b1163.116 для Windows x64 скачивается в `.gradle/hotswap/`, проверяется по закреплённому SHA-512 и распаковывается в кеш проекта. Размер загрузки — около 94 МБ. Системная Java, `JAVA_HOME`, обычный `runClient` и версия Java для сборки не меняются. Источник: [JetBrains Runtime](https://github.com/JetBrains/JetBrainsRuntime), [закреплённый релиз](https://github.com/JetBrains/JetBrainsRuntime/releases/tag/jbr-release-21.0.11b1163.116).

1. Один раз запустите из папки проекта: `./gradlew.bat runHotSwapClient`. Дождитесь главного меню и зайдите в мир или на сервер.
2. После изменения Java-кода выполните во втором терминале: `./gradlew.bat reloadCode`.
3. Дождитесь `BUILD SUCCESSFUL` и строк `[HotSwap] Updated`. Следующие вызовы изменённых методов выполняются с новым кодом в том же клиенте. Регистрация новых функций выполняется на клиентском потоке, открытый Click GUI обновляется автоматически.

`reloadCode` сам компилирует код и ресурсы, затем через штатный JDK HotSwap обновляет только изменённые загруженные классы. Состояние объектов сохраняется; конструкторы и статические инициализаторы существующих классов повторно не вызываются. После применения кода инструмент запрашивает регистрацию на следующем клиентском тике и ждёт подтверждения. `LiveReload.initializeOnce(...)` вызывает `initialize()` только у новых компонентов: существующие обработчики и HUD-слои не дублируются. Если инициализация упала после частичной регистрации, повторная попытка блокируется до перезапуска.

Чтобы новый модуль появился без перезапуска:

1. Создайте отдельный класс модуля с `public static void initialize()` и, если нужен переключатель, `public static void setEnabled(boolean)` по образцу существующих модулей.
2. В `StormVisualsClient.initializeModules()` добавьте `LiveReload.initializeOnce(dev.stormvisuals.module.NewModule.class);` перед инициализацией `HudRenderSystem`. Весь новый код и поля размещайте в новом классе.
3. В `ClickGuiScreen.createModules()` добавьте карточку `new Module("New Module", "", "Описание", "Utils", false, false)`, а в существующий `configureUtility(...)` — `case "New Module" -> dev.stormvisuals.module.NewModule.setEnabled(module.enabled);`.
4. Выполните `reloadCode`: класс загрузится, события зарегистрируются, новая карточка появится в меню. Поддерживается и добавление HUD-слоёв через `HudRenderSystem.addLayer(...)` во время этой регистрации. Состояния и бинды существующих карточек сохраняются.

У нового модуля должен быть уникальный идентификатор карточки (имя); существующие карточки при обновлении не удаляются и не переименовываются. Бинды добавленных на ходу модулей доступны в самом моде и сохраняются в его конфиге; в стандартном меню управления Minecraft они появятся после перезапуска (Fabric запрещает позднюю регистрацию `KeyMapping`). Новые модули должны сами обрабатывать текущий мир и очищать своё состояние при его смене; прошедшие события входа в мир не воспроизводятся. Максимум — 64 карточки, как в существующем формате конфига.

В новом `runHotSwapClient` проверены **добавление и удаление полей, методов и компонентов `record`** в уже загруженных классах, включая обновление вызывающего кода одной пачкой. Это устраняет ограничение стандартной JVM, которое давало `changes to class attribute not implemented`, например при добавлении `texture` в `HudListPanel.Row`. Уже запущенную обычную JVM переключить на JBR нельзя: один раз закройте клиент и снова запустите `runHotSwapClient`.

Старые объекты сохраняют значения старых полей, а новые поля у существующих объектов и классов получают значения JVM по умолчанию (`null`, `0`, `false`). Старые конструкторы и статические инициализаторы **не выполняются заново**: новый список, шейдер или другой кеш нужно явно создать в коде либо перезапустить клиент. Уже выполняющийся метод может закончить работу по старому коду. Изменение наследования и сложных связей классов не гарантируется. Изменённые/новые mixin-классы, удалённые классы и стартовые ресурсы (включая `fabric.mod.json` и `stormvisuals.mixins.json`) по-прежнему блокируют обновление с требованием перезапуска; отклонённая JVM пачка классов не применяется.

Для обновлённых файлов в `assets/` после `reloadCode` нажмите `F3 + T`; собственные кеши шрифтов/шейдеров могут потребовать перезапуска.

Режим действует только для клиента, запущенного через `runHotSwapClient`, и не заменяет JAR в обычном лаунчере. Он использует локальный порт `127.0.0.1:5006`; одновременно допускается один такой клиент, подключение отладчика IDE нужно закрыть перед `reloadCode`. После `clean` запустите клиент заново. Внешний инструмент находится в отдельном `devTools` source set и не включается в JAR мода. Клиентский обработчик запросов включён только в среде разработки с `-Dstormvisuals.hotSwap=true`; обычный `runClient` не открывает порт отладки.

Установка runtime без запуска игры: `./gradlew.bat setupHotSwapRuntime`. Проверка стандартной JVM: `./gradlew.bat hotSwapChecks` (входит в `build`). Проверка расширенного режима: `./gradlew.bat hotSwapEnhancedChecks`; она запускает отдельную тестовую JVM на том же JBR с тем же флагом, проверяет изменение структуры и сохранение состояния. Эти тесты не запускают Minecraft. Обычная сборка не требует скачивать JBR; при отсутствии кеша перед первым запуском/расширенным тестом нужен интернет, после установки поддерживается `--offline`.
